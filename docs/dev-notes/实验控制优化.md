# TMH系统实验控制优化

## 问题描述

原始设计中，程序启动后会立即开始数据采集和绘图，即使用户还没有开始实验。这导致：

1. **不必要的数据库写入** - 实验前的数据被写入数据库
2. **资源浪费** - CPU和内存被不必要的绘图操作占用
3. **数据污染** - 实验数据库包含大量非实验期间的数据
4. **用户体验差** - 界面显示与实际实验状态不符

## 优化方案

### 1. 移除自动启动数据采集

**修改文件**: `src/ui/integrated_control_page.py`

**问题点**:
```python
# 原来的自动启动逻辑
self.device_check_timer.start(2000)  # 延迟2秒检查设备状态
```

**优化后**:
```python
# 移除自动启动数据采集的逻辑
# 数据采集和绘图只在用户主动开始实验时启动
self.device_check_timer = QTimer(self)
self.device_check_timer.timeout.connect(self.check_device_and_start_acquisition)
self.device_check_timer.setSingleShot(True)
# 不再自动启动：self.device_check_timer.start(2000)
```

### 2. 增加实验状态控制

**修改文件**: `src/device_clients/data_handler.py`

**新增功能**:
- 添加 `experiment_running` 状态标志
- 提供 `set_experiment_running()` 和 `is_experiment_running()` 方法
- 只在实验运行时保存数据到数据库

**关键代码**:
```python
# 实验状态控制 - 只在实验运行时保存数据
self.experiment_running = False

def set_experiment_running(self, running: bool):
    """设置实验运行状态，控制数据库保存"""
    self.experiment_running = running
    if running:
        self.logger.info("数据处理器：实验开始，启用数据库保存")
    else:
        self.logger.info("数据处理器：实验停止，禁用数据库保存")

# 只在实验运行时才保存数据到数据库
if self.experiment_running and db_has_changes and (temp_payload or weight_payload or flows_payload):
    # 数据入库逻辑
```

### 3. 集成实验控制到UI

**修改文件**: `src/ui/integrated_control_page.py`

**开始实验时**:
```python
# 通知数据处理器实验开始（启用数据库保存）
if self.data_handler and hasattr(self.data_handler, 'set_experiment_running'):
    self.data_handler.set_experiment_running(True)
```

**停止实验时**:
```python
# 通知数据处理器实验停止（禁用数据库保存）
if self.data_handler and hasattr(self.data_handler, 'set_experiment_running'):
    self.data_handler.set_experiment_running(False)
```

### 4. 绘图控制优化

**修改绘图更新条件**:
```python
# 只有在实验运行、有数据且正在采集时才更新绘图
if not (self.experiment_running and self.is_collecting and self.data_received and len(self.global_times) > 0):
    return
```

## 优化效果

### 数据管理改进
- ✅ **纯净的实验数据** - 数据库只包含实验期间的有效数据
- ✅ **减少存储占用** - 避免大量非实验期间的数据写入
- ✅ **提高数据质量** - 实验数据与非实验数据完全分离

### 性能优化
- ✅ **降低CPU使用** - 非实验期间不进行不必要的绘图
- ✅ **减少内存占用** - 避免绘图数据的持续累积
- ✅ **提高响应性** - 系统资源更好地分配给实际需要的功能

### 用户体验提升
- ✅ **明确的状态控制** - 用户可以明确控制何时开始数据采集
- ✅ **准确的数据显示** - 绘图只在实验运行时更新
- ✅ **符合逻辑的流程** - 启动程序→设置参数→开始实验→数据采集

## 工作流程

### 优化前的流程
```
程序启动 → 立即开始数据采集 → 立即开始绘图 → 立即写入数据库
           ↑ 问题：即使没有实验也在运行
```

### 优化后的流程
```
程序启动 → 等待用户操作 → 用户开始实验 → 启动数据采集 → 开始绘图 → 写入数据库
                         ↑ 只有实验开始后才激活数据处理
```

## 向后兼容性

所有修改都保持了API的向后兼容性：
- DataHandler的现有接口保持不变
- 新增的方法使用hasattr检查，确保在老版本中不会出错
- UI控制逻辑优雅地集成到现有的实验流程中

## 测试建议

1. **启动测试** - 验证程序启动后数据库不会立即写入数据
2. **实验流程测试** - 验证开始实验后数据采集和绘图正常工作
3. **停止测试** - 验证停止实验后数据库写入停止
4. **状态切换测试** - 验证多次开始/停止实验的状态切换正确
