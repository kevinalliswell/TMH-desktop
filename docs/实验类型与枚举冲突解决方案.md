# 实验类型与枚举冲突解决方案

## 问题描述

原系统存在以下冲突：

1. **硬编码的枚举类型**：`ExperimentType` 枚举只定义了3种标准实验类型
2. **动态配置的实验模式**：通过 `experiment_modes.json` 可以配置无限数量的自定义实验模式
3. **映射冲突**：`integrated_control_page.py` 中的 `mode_mapping` 硬编码了3种标准模式的映射

## 解决方案

### 1. 创建实验类型管理器 (`ExperimentTypeManager`)

**文件位置**: `src/services/experiment_type_manager.py`

**核心功能**:
- 统一管理标准实验类型和自定义实验类型
- 提供类型查找、分类判断、模式映射等功能
- 支持动态加载和保存自定义实验类型
- 向后兼容原有的枚举系统

**主要类**:
- `ExperimentTypeInfo`: 实验类型信息类，包含类型ID、名称、描述、分类等
- `ExperimentTypeCategory`: 实验类型分类枚举（标准/自定义）
- `ExperimentTypeManager`: 实验类型管理器

### 2. 更新模式映射逻辑

**文件**: `src/ui/pages/integrated_control_page.py`

**改进**:
- 使用 `ExperimentTypeManager` 替代硬编码的映射
- 支持动态加载的实验模式
- 统一处理标准和自定义实验类型

**关键方法**:
```python
def _get_experiment_type_from_mode_id(self, mode_id):
    """根据模式ID获取实验类型"""
    # 使用实验类型管理器获取类型信息
    type_info = self.experiment_type_manager.get_type_by_id(mode_id)
    # 标准模式映射到ExperimentType枚举
    # 自定义模式返回None（需要特殊处理）
```

### 3. 更新实验控制器

**文件**: `src/ui/experiment/experiment_controller.py`

**新增功能**:
- `set_experiment_mode_by_id()`: 根据模式ID设置实验模式（支持自定义模式）
- 支持自定义实验类型的名称显示
- 向后兼容原有的枚举系统

**处理逻辑**:
- 标准模式：映射到对应的 `ExperimentType` 枚举
- 自定义模式：使用还原性实验作为基础，但保存自定义模式名称

### 4. 更新实验对话框

**文件**: `src/ui/dialogs/experiment_dialog.py`

**改进**:
- 使用 `ExperimentTypeManager` 加载实验类型选项
- 支持标准和自定义实验类型的统一显示
- 保持原有的UI交互逻辑

## 技术特点

### 1. 向后兼容
- 保持原有的 `ExperimentType` 枚举不变
- 标准实验类型继续使用枚举系统
- 现有代码无需大幅修改

### 2. 扩展性
- 支持无限数量的自定义实验类型
- 通过配置文件管理实验类型
- 支持动态添加、删除、修改实验类型

### 3. 统一管理
- 所有实验类型通过 `ExperimentTypeManager` 统一管理
- 提供一致的API接口
- 支持类型查找、分类判断、模式映射等功能

### 4. 配置驱动
- 自定义实验类型通过 `experiment_modes.json` 配置
- 支持导入导出实验配置
- 实时加载配置变更

## 使用示例

### 1. 获取所有实验类型
```python
manager = ExperimentTypeManager()
all_types = manager.get_all_types()
```

### 2. 添加自定义实验类型
```python
custom_type = ExperimentTypeInfo(
    type_id="CUSTOM_TEST",
    name="自定义测试实验",
    description="测试用实验",
    category=ExperimentTypeCategory.CUSTOM,
    enabled=True
)
manager.add_custom_type(custom_type)
```

### 3. 设置实验模式
```python
# 标准模式
controller.set_experiment_mode(ExperimentType.REDUCIBILITY)

# 自定义模式
controller.set_experiment_mode_by_id("CUSTOM_TEST")
```

## 总结

通过引入 `ExperimentTypeManager`，成功解决了实验类型与枚举的冲突问题：

1. **保持兼容性**：原有代码无需大幅修改
2. **支持扩展**：可以无限添加自定义实验类型
3. **统一管理**：所有实验类型通过统一接口管理
4. **配置驱动**：通过配置文件管理实验类型，支持动态加载

这个解决方案既解决了当前的冲突问题，又为未来的功能扩展提供了良好的基础。
